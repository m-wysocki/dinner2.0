# 03.2: Mobile screen-level routing and loading/error tests

**What to build:** Automated tests for observable mobile screen behaviour, covering routing and loading/success/error states.

**Blocked by:** 03: Mobile bootstrap and API client

**Status:** ready-for-agent

## Background

Follow-up from the code review of 03. The spec's testing decisions require that "mobile tests cover observable screen behaviour and API contract usage rather than component internals" (spec.md). Today only the pure functions are covered (`submitRegistration`, `apiClient`); the actual register screen (loading spinner, success state, error presentation) and base navigation have no screen-level tests. Rendering React Native components is not yet possible because `@testing-library/react-native` is not installed.

## What to do

- Add the required testing dependency and test environment configuration for rendering React Native components.
- Add screen-level tests for the register screen: submitting shows a loading state, success shows the pending-activation message, and an API error is presented.
- Add a basic navigation/routing test for the mobile shell (e.g. the root to the register route).

## Definition of done

- [ ] `@testing-library/react-native` (or equivalent) is installed and configured.
- [ ] Register screen tests cover loading, success, and error presentation.
- [ ] A basic navigation/routing test exists for the mobile shell.
- [ ] Mobile typecheck, tests, lint, formatting, and workspace test suite pass.
