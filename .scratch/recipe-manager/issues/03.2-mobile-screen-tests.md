# 03.2: Mobile screen-level routing and loading/error tests

**What to build:** Automated tests for observable mobile screen behaviour, covering routing and loading/success/error states.

**Blocked by:** 03: Mobile bootstrap and API client

**Status:** resolved

## Background

Follow-up from the code review of 03. The spec's testing decisions require that "mobile tests cover observable screen behaviour and API contract usage rather than component internals" (spec.md). Today only the pure functions are covered (`submitRegistration`, `apiClient`); the actual register screen (loading spinner, success state, error presentation) and base navigation have no screen-level tests. Rendering React Native components is not yet possible because `@testing-library/react-native` is not installed.

## What to do

- Add the required testing dependency and test environment configuration for rendering React Native components.
- Add screen-level tests for the register screen: submitting shows a loading state, success shows the pending-activation message, and an API error is presented.
- Add a basic navigation/routing test for the mobile shell (e.g. the root to the register route).

## Definition of done

- [x] `@testing-library/react-native` (or equivalent) is installed and configured.
- [x] Register screen tests cover loading, success, and error presentation.
- [x] A basic navigation/routing test exists for the mobile shell.
- [x] Mobile typecheck, tests, lint, formatting, and workspace test suite pass.

## Resolution

Installed `@testing-library/react-native@14` (with its `test-renderer` peer, which replaces the deprecated `react-test-renderer` and is compatible with the pinned React 19.1 / RN 0.81 toolchain) and wired up a screen-level test environment for the mobile package:

- `vitest.config.ts` aliases `react-native` to a thin host-component mock (`test/mocks/react-native.js`) so screen imports render through RNTL's test renderer in Node, and uses the automatic JSX runtime (Expo's tsconfig forces the classic runtime).
- `test/setup.ts` redirects Node's bare `react-native` resolution to the same mock, because RNTL loads as CommonJS and its matchers/helpers (`StyleSheet.flatten`) natively `require('react-native')`, bypassing Vite's alias; the real package is Flow-typed and cannot load in Node.
- `test/expo-router-mock.tsx` provides `Link`, `Stack`, `Tabs`, `useRouter`, `useSegments`, and a `router` spy so screens render without the native navigation stack.

Tests added:
- `test/register-screen.test.tsx` (4): form renders, loading state while submitting (inputs disabled, submit label replaced by spinner, no double navigation), success shows the pending-activation message, and an API error message is presented.
- `test/routing.test.tsx` (2): the root screen navigates to `/register`, and the register screen links back to `/`.

Verified: mobile tests (15), typecheck, lint, build, and `format:check` pass; the full workspace test suite (shared 13, api 18, mobile 15), workspace typecheck, and lint pass; `expo export --platform ios` still bundles successfully.
